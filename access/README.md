# Доступы и ключи — организация

Этот каталог хранит структуру для локального файла с доступами к сервисам проекта.

## Как это устроено

- `credentials.local.txt` — сам файл с реальными логинами/паролями/ключами.
  Он **не коммитится в git** (см. `.gitignore` в корне репозитория) и существует
  только на вашей машине/в вашей рабочей копии. Это сделано намеренно: репозиторий
  на GitHub — не место для хранения реальных секретов (даже в приватном репо они
  попадают в историю коммитов навсегда и могут утечь при форке/приглашении
  соавтора/смене видимости репо).
- `credentials.template.txt` — пустой шаблон со структурой разделов, который
  можно коммитить и обновлять в репозитории — по нему видно, какие доступы
  вообще должны быть заведены, без самих значений.

## Как пользоваться

1. Скопируйте `credentials.template.txt` → `credentials.local.txt` (если ещё не сделано).
2. Заполните реальными значениями.
3. Когда появляется новый сервис/ключ — сначала добавьте раздел в шаблон
   (закоммитьте), потом впишите значение в свой `credentials.local.txt`.

## Рекомендации по безопасности

- Не отправляйте `credentials.local.txt` в чат целиком и не публикуйте его содержимое.
- Если ключ когда-либо "утёк" (засветился в переписке, скриншоте, публичном репо) —
  считайте его скомпрометированным и перевыпустите.
- Для долгосрочного хранения лучше держать копию в менеджере паролей
  (1Password, Bitwarden и т.п.), а этот файл использовать как рабочую шпаргалку
  для локальной разработки/деплоя.
