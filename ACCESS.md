# Доступы и ключи — организация

Реальные логины/пароли/ключи хранятся в `.env` — он в `.gitignore` и никогда
не попадает в git/GitHub.

`.env.example` — шаблон со списком переменных (без значений), он коммитится,
чтобы было видно, какие доступы вообще нужно завести.

## Локально на своей машине

```
cp .env.example .env
```

и заполнить `.env` реальными значениями.

## В сессиях Claude Code on the web (claude.ai/code)

Здесь каждая сессия — новый контейнер, склонированный из git с нуля, поэтому
gitignore-файл сам по себе между сессиями не сохраняется. Чтобы `.env` был
доступен в каждой новой сессии без коммита секретов в репозиторий:

1. На [claude.ai/code](https://claude.ai/code) откройте иконку облака
   (текущее окружение) в строке над полем ввода → шестерёнка настроек
   окружения проекта.
2. В поле **Environment variables** вставьте реальные `KEY=value` — по одной
   переменной на строку, имена как в `.env.example`. Это НЕ git — значения
   видны только тем, кто использует это окружение.
3. Сохраните.

С этого момента `SessionStart`-хук (`.claude/hooks/session-start.sh`,
подключён через `.claude/settings.json`) при старте каждой новой сессии сам
собирает `.env` из этих переменных — Claude сможет прочитать файл `.env`
как обычно, без напоминаний.

Появился новый сервис — сначала добавьте переменную в `.env.example`
(коммитом в репозиторий), потом впишите значение в Environment variables
окружения (и/или в свой локальный `.env`).

## Почему не в самом репозитории

Даже в приватном репозитории секреты, попавшие в историю коммитов,
остаются там навсегда и могут утечь при форке, смене видимости репо или
добавлении соавтора. `.env` с реальными значениями должен оставаться
только локально.

## Дополнительно

- Для долгосрочного/командного хранения лучше держать копию в менеджере
  паролей (1Password, Bitwarden и т.п.) — `.env` использовать как рабочую
  копию для локальной разработки.
- Если какой-то ключ "засветился" (в переписке, скриншоте, публичном
  месте) — считайте его скомпрометированным и перевыпустите.
