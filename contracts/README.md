# Договори

## Вхідні дані (від Каті)
1. Послуга — `seo` (PPC — шаблон буде пізніше)
2. На кого наші реквізити — файл у `entities/` (зараз: `turchykhin`)
3. Реквізити клієнта
4. Сайт
5. План робіт
6. Сума (USD за комерційним курсом ПриватБанку або фіксовано в грн)

## Як зібрати
1. Створити `orders/<YYYY-MM-DD>_<site>.yaml` за зразком `orders/2026-10-20_zvlegal.com.yaml`.
2. `python3 contracts/build.py contracts/orders/<файл>.yaml`
3. Готовий файл: `output/Договір_<SERVICE>_<site>_<MM-YYYY>.docx`

## Правила
- Номер договору = дата `ДДММРР/1` (напр. 20.10.2026 → `201026/1`). Дата за замовчуванням — сьогодні.
- Мова — українська.
- Сума завжди цифрами і прописом.
- Перевіряти IBAN (контрольна сума mod 97) і що в тексті не лишилось даних з попереднього клієнта.
- Шаблон `templates/seo.docx` — оригінальний договір (flytechnology.ua); скрипт замінює в ньому
  номер/дату, преамбулу Замовника, сайт у п. 3.2.1, план і вартість у Додатку 1, блок «ЗАМОВНИК».
- Блок Виконавця в шаблоні — ФОП Турчихін. Для іншої нашої особи треба додати `entities/<id>.yaml`
  і заміну блоку Виконавця в `build.py`.

## Правки від клієнта (коментарі в .docx)
- Вносимо лише погоджені правки (наша відповідь «ок» / «так»).
- Якщо в гілці 3+ коментарів (була дискусія) — фінальна редакція в останньому коментарі.
- Якщо відповідь переносить пункт (напр. «це в 2-ий місяць») — у поточний Додаток не вносимо.
- Коментарі з фінального файлу прибираємо. Оригінал з коментарями і скрипт правок — у `negotiations/`.
