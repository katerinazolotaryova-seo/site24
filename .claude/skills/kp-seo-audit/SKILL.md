# КП по SEO-аудиту — алгоритм сборки (модель site24 / Bettertone)

Логика продукта: КП продаёт не «нашли ошибки», а «нашли деньги, которые клиент теряет
прямо сейчас» + понятный путь их вернуть. Каждый блок закрывает одно возражение
клиента, и блоки должны идти в порядке возражений, а не в порядке удобства для
аналитика:

```
Проблема (боль) → Рынок (контекст) → Находки (экспертиза) → Приоритеты и стратегия (план)
→ Кейс (доказательство) → Команда и отчётность (риск) → Цель в деньгах (призыв к действию)
```

Референс готового результата в этом же репозитории: `SEO_Strategy_Bettertone_v3.pptx`
(15 слайдов, кейс медоборудования ×11 за 15 мес.). Новую презентацию собирать в той же
логике слайдов и с той же визуальной подачей (через `pptx`-скилл), не копируя цифры
чужого кейса.

## Когда запускать

- Просят подготовить КП / SEO-аудит для продажи / презентацию для лида или клиента.
- Дают домен проспекта и просят «сделать как для Bettertone».
- Нужно понять, какие данные и доступы собрать перед тем, как садиться за аудит.

## Порядок работы (0 → 6)

**0. Квалификация и бриф.**
Прежде чем копать — заполнить `reference/brief-checklist.md` тем, что уже известно
(домен, ниша, 3–5 конкурентов, бизнес-цель клиента). Что неизвестно — отметить как
вопросы для аккаунт-менеджера/клиента, не гадать.

**1. Доступы.**
На стадии продажи (до контракта) полноценных доступов к GSC/GA4/CMS обычно нет —
собирается публичный слепок. Полный список доступов и как их запросить —
`reference/access-checklist.md`. Если часть доступов уже дали (тёплый лид, апсейл
текущему клиенту) — использовать их, они дают более точные цифры для блоков 1, 3, 4, 6.

**2. Публичное исследование (без доступов клиента).**
Собрать всё, что закрывает блоки 1–6 из публичных источников: выдача Google, сайты
конкурентов, PageSpeed, sitemap.xml/robots.txt, WHOIS/бэклинк-чекеры с бесплатным
лимитом, ручные запросы в ChatGPT/AI Overview. Здесь же — черновая приоритизация
(блок 7).

**3. Углублённые данные (если доступы получены).**
Если клиент дал доступ к GSC/GA4/Ahrefs-проекту — уточнить трафик, конверсии,
источники трафика, реальный статус индексации (не только по `site:`).

**4. Сборка находок → приоритетов → дорожной карты.**
Свести находки в top-5–7 по влиянию (блок 7), затем разложить на 6 направлений и
3 месяца дорожной карты (блок 8), как на слайдах 5–8 референсного pptx.

**5. Сборка деки.**
Собрать презентацию через `pptx`-скилл, ориентируясь на структуру
`SEO_Strategy_Bettertone_v3.pptx` (слайд-мэппинг ниже). Кейс и команда (блоки 10)
берутся из актуальных материалов site24, не выдумываются.

**6. Контроль перед отправкой.**
Проверить: у каждой находки в разделе «Технический аудит» — привязка к деньгам/трафику
(не голый чек-лист), у каждого приоритета — ожидаемый эффект, цель проекта
сформулирована в бизнес-метриках (заказы/выручка), а не в позициях.

## Детальные блоки

Полный опросник, данные и доступы по каждому из 11 блоков — в
`reference/brief-checklist.md`. Сводный список доступов и готовый шаблон письма
клиенту на запрос доступа — `reference/access-checklist.md`. Рекомендуемые
инструменты (публичные vs требующие подписки/доступа) по каждому блоку —
`reference/tools-stack.md`.

Кратко, что нужно на входе по каждому блоку (детали — в reference-файлах):

1. **Снимок vs конкуренты** — список 3–5 прямых конкурентов + 15–30 коммерческих
   запросов ядра. Доступ: трекер позиций/видимости.
2. **Рынок и ниша** — то же плюс структура сайтов лидеров. Доступ: не нужен, только
   ручной просмотр выдачи и сайтов конкурентов.
3. **Технический аудит** — сам сайт клиента. Доступ: желательно GSC (реальная
   индексация), без него — краулер + `site:`.
4. **Семантика и коммерческие страницы** — оргструктура сайта, каталог
   услуг/товаров. Доступ: не обязателен на этапе продажи.
5. **AI-видимость** — бренд + топ-запросы. Доступ: не нужен, ручные запросы в
   ChatGPT/Gemini/Google AI Mode.
6. **Ссылочный профиль** — домен клиента + доменов 3–5 конкурентов. Доступ: свой
   аккаунт в бэклинк-чекере (Ahrefs/Serpstat/Semrush), не клиентский.
7. **Приоритизация** — результат блоков 1–6, доступ не нужен.
8. **Дорожная карта** — бизнес-контекст клиента (бюджет, сроки, приоритетные
   направления). Вопрос клиенту/аккаунту.
9. **Отчётность** — внутренний стандарт студии, не требует данных клиента.
10. **Соц. доказательство** — актуальный кейс + состав команды (внутренние
    материалы site24).
11. **Цель в деньгах** — интервью с клиентом: средний чек, маржа, текущая конверсия
    из органики, целевое число заказов/выручки в месяц.

## Важно

- Не показывать клиенту сырые данные конкурентов из платных инструментов без
  собственной подписки на них — доступы конкурентов не запрашиваются, только
  наблюдаются публично или через свой аккаунт в SEO-инструменте.
- Если часть доступов не дали — не блокировать сборку КП: помечать эти пункты как
  «уточним на этапе аудита после старта» и продавать на публичных данных, это
  нормальная практика для стадии продажи.
- Цифры чужого кейса (×11, 20 000 юзеров/мес и т.п.) переносить в новую КП только
  если это тот же кейс — для нового клиента считать по его нише.
