# Сторінка: КЕЙСИ (`/tag/kejsi/`)

[← Index](../2026-04-30-EN-site24-review.md)

**Контекст сторінки:** вітрина результатів агенції. Людина приходить через меню "Кейси" (тепла), через "Всі кейси" з SEO/PPC сторінок (тепла після оцінки послуг), або через бренд-запит "Site24 кейси / приклади" (холодна). Інтент завжди один — побачити **конкретні цифри по нішах, схожих на свою**. Тому ключова робота сторінки — швидко довести "ось що ми зробили для бізнесів як ваш", і дати фільтр, щоб користувач знайшов релевантне.

**Загальний діагноз:** ця сторінка зараз НЕ є вітриною кейсів. Це WordPress blog template з тегом "kejsi". Кейси на сайті агенції — на тегу, без фільтрів, з блог-сайдбаром і breadcrumbs "Головна / Блог /" всередині кожного кейсу. Для агенції з претензією на SEO це системний фейл сегментації контенту.

## A. Структура сторінки

**Поточна структура:**
```
URL: /tag/kejsi/  (тегова архівна сторінка WP)
↓
Breadcrumbs "Головна / Кейси Site24" →
Hero "Наші кейси" + опис →
2 хештеги (#Кейси Site24, #Юзабіліті) — не функціональні фільтри →
Grid карток (2 колонки, 8 шт) + сайдбар (Форма "Отримати консультацію" + Табе "Кейси/Топ статей" + список блог-постів) →
Пагінація "1 [2]" →
Футер
```

**Поточна картка кейсу (превью):**
- Скрін Google Analytics (для SEO/PPC) — часто без брендингу клієнта
- Бейджі "#Кейси Site24" + дата
- Заголовок (типу "PPC для e-commerce: зростання доходу в 2,5 рази за один рік")
- Підпис автора ("Автор: Денис Іванов")
- БЕЗ: логотипа клієнта на превью, метрик у вигляді цифр, бейджа типу послуги (SEO/PPC)

**Що ламає:**

1. **URL `/tag/kejsi/` — тегова архівна сторінка WP (P0).** Для SEO-агенції мати головну вітрину кейсів на тегу — антипатерн. Має бути окремий Custom Post Type "Cases" (або "Кейси") з кастомним постійним URL `/cases/` або `/keisi/`. Зараз меню "Кейси" → веде на тег. Якщо хтось скопіює URL — у нього `tag/kejsi/`, що SEO-неоптимально і непрезентабельно.

2. **Breadcrumbs внутрішнього кейсу: "Головна / Блог / [назва кейсу]" (P0).** Кейс відкривається з категорії "Блог" — тобто на бекенді кейси = блог-пости з тегом. Перенести в окремий CPT, breadcrumb має бути "Головна / Кейси / [назва]".

3. **Сайдбар із блог-шаблону (P0).** Праворуч на гриді кейсів — форма "Отримати консультацію" + табе "Кейси / Топ статей" + список блог-статей. Це повний blog template, не cases template. Прибрати сайдбар взагалі (для full-width гріду) або замінити форму на коротку панель фільтрів.

4. **Немає фільтрів за типом послуги (P0).** 8 кейсів змішано: SEO + PPC + Аналітика. Холодний користувач, який шукає "Site24 SEO кейси" — мусить вгадувати з заголовка. Має бути таби або чіпи: `Всі / SEO / PPC / SERM / Аналітика`. Це базовий патерн вітрини агенції.

5. **Превью без логотипів клієнтів і без метрик-цифр на картці (P0).** Зараз превью — скрін Google Analytics і заголовок. Користувач не бачить ні бренд клієнта, ні KPI результату. Має бути: логотип клієнта (де є дозвіл) + 1-2 ключові цифри ("+251% конверсій" / "Топ-3 за 6 міс" / "ROAS 4.5x").

6. **Бейдж "#Кейси Site24" замість типу послуги (P0).** Зараз єдиний бейдж — це назва тегу. Замінити на тип-маркер: `SEO / PPC / SEO+PPC / Аналітика / SERM`.

7. **Свіжість пулу кейсів: 2 за 2025, 1 за 2023, решта 2021-2022 (P1).** Якщо агенція робить "1000+ проектів за 9 років" — то за 4 роки опубліковано 8 кейсів. Виглядає як "не пишемо кейси", що б'є по позиціонуванню. Підтвердити з власницею: чи це реально весь пул, чи частина не виставлена. Якщо більше — додати свіжі 2024-2025.

8. **Підпис "Автор: Денис Іванов" / "Автор: Катерина Золотарьова" на превью (P1).** Метадата блог-поста, для cases templates автор зайвий. Прибрати з картки превью (можна лишити всередині кейсу як секцію "Хто вів проект").

9. **Хештеги "#Кейси Site24" і "#Юзабіліті" вгорі (P2).** Ведуть на інші теги, не функціональні фільтри. Прибрати або замінити на справжні фільтри (див. п.4). "Юзабіліті" як окремий тег без контексту — викликає питання.

10. **Breadcrumbs вгорі: "Головна / Кейси Site24" (P1).** "Кейси Site24" — назва тегу, у вітрини має бути просто "Кейси".

11. **Поле "Пошук по блогу" у сайдбарі (P2).** Окрім того що сайдбар треба прибрати, текст "Пошук по блогу" на сторінці кейсів — фейл копіпасту. Якщо лишати пошук — мав би бути "Пошук по кейсах".

**Переписати:**

## C. Візуальні правки

1. **Картка кейсу: додати логотип клієнта і 1-2 метрики (P0).** Зараз превью — скрін Google Analytics. Має бути: логотип клієнта (де є дозвіл) + KPI у форматі бейджа: "+251% конверсій" / "Топ-3 за 6 міс" / "ROAS 4.5x" / "$2.66 CPC при $52K обороту".
2. **Бейдж типу послуги на картці (P0).** Кольорове кодування: SEO зелений, PPC синій, SERM помаранчевий тощо. Зараз синій бейдж "#Кейси Site24" однаковий у всіх.
3. **Грід full-width замість 2 колонки + сайдбар (P1).** Зараз 2 колонки занадто стиснуті, картки тонкі. Full-width зі стандартним 3-колонним грідом дасть кращу читаність.
4. **Hero вузький, "Наші кейси" + опис вирівняні зліва-справа з великим вільним простором (P2).** Можна сильніше — додати фон з прев'юшками всіх кейсів або великими цифрами "1000+ / 9 років / 30 ніш" з переходом до гріду.
5. **Внутрішня сторінка кейсу: TOC справа і структура секцій (Про клієнта / Специфіка / Цілі) — добре зроблено, не чіпати.** Це плюс, який можна використати як референс структури.
6. **Внутрішня сторінка: бейдж типу послуги + логотип клієнта поряд із заголовком (P1).** Зараз тільки заголовок і "#Кейси Site24" + дата + аватар автора.

## D. Структурні правки

### Перебудувати

1. **Перенести кейси з тегу в окремий Custom Post Type "Cases" (P0).** WordPress дозволяє створити CPT через ACF Pro або CPT UI. Постійний URL `/cases/[slug]` або `/keisi/[slug]`. Старі URL `/tag/kejsi/` → 301 редирект на нову вітрину. Внутрішні URL кейсів (типу `/ppc-dlya-e-commerce-zrostannya-dohodu-v-25-razi-za-odin-rik/`) — теж 301 редирект на `/cases/ppc-dlya-e-commerce.../`.

2. **Шаблон вітрини кейсів — окремий, не блог-шаблон (P0).** Без сайдбара з пошуком блогу. З фільтрами вгорі + грід full-width. Можна на вітрині додати міні-блок із 3 топ-кейсами зверху ("Найкращі результати"), а далі вже всі.

### Додати

1. **Фільтри: Все / SEO / PPC / SERM / Аналітика (P0).** Хедер вітрини після hero. Клік по фільтру — сторінка не перезавантажується, кейси переключаються.
2. **Фільтр за нішою (опціонально, P1).** E-commerce / Послуги / Медицина / B2B / Освіта — за результатами повного пулу (поки 8-16 кейсів, можливо нішевий фільтр зайвий, додати коли буде 30+).
3. **На превью картки додати: логотип, метрики, тип послуги (P0).** Див. C.1, C.2.
4. **CTA-форми — три точки контакту (P1).** Контекст специфічний: людина на цій сторінці порівнює і сумнівається, не готова писати "обговорити проект". Тому стандартний hard-CTA слабкий. Натомість — м'які intent-CTA з прив'язкою до контексту перегляду:

   **a) CTA внизу вітрини, після пагінації.** Заголовок: `Не знайшли кейс у своїй ніші?`. Підпис: `Розкажіть про свій бізнес — підготуємо персональний прорахунок`. Поле: URL сайту + кнопка `Замовити прорахунок`. Це для тих, хто пройшов всю вітрину і не знайшов релевантного.

   **b) CTA всередині кожного кейсу, після останньої секції.** Заголовок з предзаповненим контекстом: `Хочете схожий результат для свого бізнесу?`. Внизу — кнопка `Замовити схожий проект`, що веде на форму з предзаповненим полем "Цікавить: [назва кейсу]". Це intent-CTA для людини, що дочитала кейс і впізнала себе.

   **c) Опціонально — мікро-CTA "Хочу так само" на картці превью (P2).** Кнопка внизу картки → модалка з 1 полем (URL сайту). Дає швидкий вхід на емоції "ого, такий же кейс як мій бізнес", без переходу всередину.

5. **Прибрати поточну sidebar-форму "Отримати консультацію" (P0).** Це блог-патерн (push форма поряд з гридом), заважає перегляду. Замість неї — CTA з п.4a у природному місці воронки.

### Уточнити з власницею

1. **Чи це повний пул кейсів?** 8 на 1-й сторінці + сторінка 2 = ~14-16 кейсів. Якщо більше — підняти на сайт. Якщо ні — програма публікації нових за 2024-2025 (наприклад, 1 кейс/місяць).
2. **Які кейси можна показати з логотипом клієнта**, а які — анонімно. Зараз логотипів немає взагалі — це обережно, але втрачає бренд-вагу. Узгодити з кожним клієнтом окремо.
3. **Які кейси є комбо SEO+PPC.** Studix.eu з PPC-сторінки виглядає як комбо (SEO трафік х10 + PPC конверсії 251%). Якщо комбо — позначити окремим типом-бейджем.
